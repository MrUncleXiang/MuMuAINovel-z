# 技术设计：项目深复制 v2

## 接口

创建请求包含新书标题、模式（仅设定/继承进度）和可选检查点 ID。后端根据检查点决定截止章，不接受前端自行拼“复制哪些分析表”。响应返回新项目 ID、复制模式、截止章和各类数据计数。

## 复制顺序

项目与创作配置 → 职业 → 角色 → 角色职业 → 关系 → 组织及成员 → 大纲 → 章节骨架/正文 → 分析与记忆 → 伏笔 → 生成历史 → 目标实体状态 → 新的空闲 Pipeline。

每类数据建立旧 ID 到新 ID 映射，外键和 JSON 中的角色、章节、记忆、伏笔引用都必须转换。X 后章节只保留骨架，正文及过程状态为空。

## 原子性

关系数据库使用一个事务。向量记忆写入新项目自己的 Chroma 集合；任一向量或数据库步骤失败，都回滚数据库并删除目标集合。新项目只在全部完成后对书架查询可见。

## 来源关系

本轮不增加源书实时关联，也不依赖 `derived_from_project_id`。若未来需要审计来源，另行新增只读元数据；它永远不能成为联动更新关系。

## 安全

后端验证源项目归属、检查点有效性和所有资源引用。API Key、MCP 凭据、运行中任务、锁、未采用候选和源 Pipeline 状态不复制。
