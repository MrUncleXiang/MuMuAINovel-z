# PRD：持久化对比项目克隆与来源关联

## 目标

从已有项目创建一份可长期管理的副本。副本属于同一用户，拥有新的项目/子数据 ID，并在书架中独立显示。

## 已决定的复制模式

用户在创建副本面板选择其中之一：

1. **从头开始**：复制完整静态设定和章节骨架，所有章节正文与过程数据为空。
2. **继承至第 X 章**：复制第 1～X 章正文，并复制所有支撑第 X+1 章继续创作的项目过程状态。包括对应章节分析、记忆、伏笔、角色状态、关系、组织状态、职业进度和生成历史。X 之后的章节保留骨架但正文与过程数据为空。

任何复制的数据都必须生成新 ID 并重新连接到副本数据；源书和任何副本间不得共享可写记录。

## 待审计后实现

- 静态设定、职业体系、默认写作风格、章节骨架的表级复制清单；
- “继承至第 X 章”涉及的过程数据表、关联映射和章节范围规则；
- `derived_from_project_id`、来源快照版本和模型标签的持久化方式；
- 重复克隆、失败回滚和并发克隆规则。
- 向量记忆以新项目 ID 建立独立集合并重新写入，不复用源项目 `vector_id`；
- 对源书已推进超过 X 的情况，只有形成了可靠章节状态快照后才允许选择该 X；否则 MVP 只能继承到最新连续已分析章节。

## 验收

- 副本可独立打开、删除、导出和启动原有项目功能；
- 源项目任何字段、流水线和创作进度不被修改；
- 副本的所有外键均指向副本数据；
- 修改 A 书的正文、分析、角色、关系、组织、职业或流水线配置后，B 书和源书的数据不变；
- 克隆失败无半成品；
- 复制清单和过程数据策略有自动化测试覆盖。

## 依赖

- 项目创作配置可深复制；
- 章节状态检查点可提供可靠继承节点；
- Pipeline 使用正式生命周期，但克隆后默认不自动启动。
