# PRD：项目创作配置所有权与快照

## 目标

明确“用户全局资源”和“单本书创作配置”的关系，使副本可以默认继承源书的选择，又能在书内独立修改而不改变其他书。

## 当前事实

- AI 服务、默认任务路由是用户级数据；
- MCP 插件是用户级数据，包含连接信息和凭据；
- Skill 定义由服务器文件目录加载，目前不是项目级数据；
- 写作风格定义属于全局预设或用户级资源，只有默认风格关联是项目级；
- 流水线 `config_snapshot` 是项目级，但目前缺 Skill、风格、MCP，且分析模型运行时未使用。

## 设计要求

1. 定义统一的项目创作配置快照，至少包含章节服务/模型、分析服务/模型、Skill 选择与版本、写作风格选择与必要内容版本、MCP 使用策略、叙事视角、字数、温度、预算和检查点。
2. 项目快照不得保存 API Key、MCP headers/env 等凭据；只引用当前用户有权使用的全局资源。
3. 书内修改“本书使用什么”只改本项目快照，不改用户全局资源定义。
4. 全局资源被改名、禁用或删除时，要定义已有项目的运行行为和明确提示，不能静默切换模型或 Skill。
5. 为可复现实验冻结会改变提示词语义的内容或版本标识，至少覆盖 Skill、写作风格和模型名。
6. 创建副本时深复制源书的项目快照；源书与副本之后分别修改。

## 交互要求

- 流水线/项目设置页能查看并修改本书的完整创作配置；
- 清楚标识“本书设置”和“所有书共享的资源管理”；
- 缺失或不可用的全局资源显示阻塞原因，不偷偷回退；
- 用户修改全局资源时提示可能影响哪些书，或由不可变快照保证既有书不受影响。

## 验收

- 修改 A 书的模型、Skill、风格、MCP 策略和分析模型后，B 书快照不变；
- 副本初始快照与源书在复制时一致，但主键和后续修改独立；
- 数据库项目记录中不存在复制出来的 API Key 或 MCP 凭据；
- AI 调用日志能追踪本次实际使用的项目配置和资源版本；
- 全局资源失效时行为有自动化测试和可理解的界面提示。

## 非目标

- 不为每本书复制一套 API Key 或 MCP 服务器定义；
- 不在本任务中实现项目克隆或连续章节生成。

## 依赖

- 正式章节生命周期的运行配置接口已确定；
- 本任务完成后 Pipeline 才能消费统一项目配置。
