# PRD：双书章节对比视图

> **已移出本轮范围，禁止实施。** 本页面不是当前独立副本创作的必要条件，也不得与创建副本或启动 Pipeline 绑定。未来确认有“两本现有书并排阅读”的真实需求后再单独立项。

> 任务：08-07-compare-view（P1）
> 状态：planning

## 目标

让用户选择自己拥有的两本书，按章节编号对照阅读正文，并能在生成过程中看到两边的实时状态。

## 路由与选书

- 新增受保护路由 `/compare`，查询参数为 `left`、`right` 项目 ID。
- 页面顶部提供两个项目选择框；只能选择当前用户的项目，两边不能是同一本。
- 三入口创建成功后直接带 A/B 项目 ID 进入；直接访问页面时也可以手动选书。
- 非法或无权访问的项目显示简短中文错误，不泄露项目是否属于其他用户。

## 章节配对

- 使用 `chapter_number` 配对，禁止用标题作为标识；标题只用于展示。
- 章节导航使用两本书章节编号的并集并按数字升序排列。
- 一边缺章时仍显示另一边正文，缺失侧显示“本书尚无第 N 章”。
- 同一项目若出现重复 `chapter_number`，页面提示数据异常，不自行猜测配对。

## 阅读布局

- 桌面端左右并排，各栏固定显示书名、模型（从流水线配置快照读取）、章节标题、状态和正文。
- 手机端改为上下堆叠，先 A 后 B；不得横向挤压正文。
- 提供上一章、下一章和章节选择；按钮尺寸固定，加载状态不能引发布局跳动。
- 正文为空时按状态区分“正在生成”“生成失败”“尚未生成”，不把空字符串当正常正文。
- 任一侧失败不影响另一侧显示。

## 数据刷新

- 项目和章节以服务端为准，不把正文持久化到浏览器。
- 任一侧存在运行中/等待中的章节或流水线时每 5 秒刷新；两边均进入终态后停止轮询。
- 切换项目或离开页面时取消旧请求和定时器，避免旧响应覆盖新选择。

## 验收

1. 标题不同但 `chapter_number` 相同的章节正确并排；同名但编号不同的章节不会错配。
2. A 有第 1-3 章、B 有第 1 和 3 章时，导航仍有 1-3，B 的第 2 章显示缺章状态。
3. 一侧加载或生成失败时，另一侧正文仍可阅读。
4. URL 可刷新和分享给同一账号使用，项目选择会同步更新查询参数。
5. 生成中的正文和状态会自动刷新，进入终态后停止轮询。
6. 桌面为双栏，手机为上下布局；长标题、长模型名和长正文不重叠、不撑破容器。
