# 多 LLM 同条件候选版本比较

## Goal

让用户对同一章节、大纲或分析请求选定 2–4 套 LLM 配置，在冻结的同一输入条件下得到多份可长期共存的候选，并对比、重试和采用其中一份。

## Requirements

- 一个正式内容对应多个候选，不复制多个正式章节。
- 每批候选共享不可变输入快照、提示词版本和生成参数，确保比较公平。
- 每个候选记录供应商/模型快照、状态、耗时、Token、错误及调用日志关联。
- 单个候选失败不影响其他成功候选；支持仅重试失败项。
- 采用候选必须确认、事务化、可重复请求且不产生二次副作用。
- 默认最多 4 个候选、并发 2 个，并提示会产生 N 次 API 调用费用。
- 旧的单模型生成流程保持可用。

## Acceptance Criteria

- [ ] 章节、大纲、分析均有独立可验收子任务。
- [ ] 同批候选可证明使用同一输入快照。
- [ ] 候选结果刷新页面后仍存在并显示真实供应商/模型。
- [ ] 可对照至少两个结果并选择正式采用项。
- [ ] 部分失败、重试、重复采用及越权访问均有明确行为。
- [ ] 低资源 VPS 上并发受控，现有单模型流程无回归。
