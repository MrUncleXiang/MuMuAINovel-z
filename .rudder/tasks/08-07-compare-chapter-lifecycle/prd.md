# PRD：正式章节与分析生命周期收敛

> 实施状态：生命周期底座与普通/后台/顺序批量入口已完成。Pipeline 配置传递按父任务拆分，见 `verification.md`。

## 目标

把普通生成、顺序批量生成、流水线、章节候选采用和分析候选采用统一接回同一条正式链路：

`正文成为正式版本 → 创建/运行分析 → 写分析与记忆 → 更新伏笔和实体状态 → 分析完成 → 允许下一章`

## 当前断点

- 章节候选采用只写正文与生成历史，不启动正式分析；
- 分析候选采用只写 `PlotAnalysis`，不应用记忆、伏笔、角色、关系、组织和职业变化；
- 流水线不等待上一章分析，并丢失 Skill、风格、MCP 和分析模型；
- 正式分析副作用集中在一个很大的后台函数中，其他入口只能复制部分代码；
- 已分析章节被替换正文或重新采用分析时，现有累加式关系/职业更新缺少可靠撤销与重算规则。

## 模块设计

建立两个可由所有入口复用的深模块：

1. **正式章节落库模块**：处理并发版本检查、正文/字数/状态、项目总字数、生成历史、旧派生数据失效、分析任务创建和幂等重试。
2. **标准分析应用模块**：把结构化分析结果原子地应用到 PlotAnalysis、StoryMemory/向量、伏笔、角色、关系、组织、职业和 AnalysisTask。

模块界面必须隐藏调用顺序和事务细节，调用者不能选择只执行一半副作用。

## 一致性规则

- 下一章开始前，上一章最新正式正文对应的分析必须 completed；
- 正文版本改变后，旧分析不得继续被当作有效上下文；
- 修改较早章节时，必须标记该章及后续依赖状态为待重算，或拒绝会造成无法恢复的不一致操作；
- 分析重试和候选重复采用必须幂等，不能重复累加亲密度、职业阶段或组织变化；
- 分析失败时保留可恢复状态，流水线暂停，不继续生成下一章；
- 分析候选的输入构建必须与普通正式分析使用同一上下文契约。

## 入口整改

- 普通单章和顺序批量生成继续使用该链路；
- 章节候选采用后自动进入该链路；
- 分析候选采用通过标准分析应用模块完成全部物化；整改前暂停采用；
- Pipeline 调用同一链路并等待分析完成；
- `batch-compare` 不作为连续创作入口，除非未来实现逐章采用和分析状态机。

## 验收

- 同一正式正文从普通生成或候选采用进入后，产生等价的分析和项目状态；
- 同一结构化分析从普通分析或候选采用进入后，产生等价的数据库与向量结果；
- 分析任务重复执行不重复更新关系、职业或组织；
- 第 N 章分析未完成/失败时，第 N+1 章不能启动；
- Pipeline 实际使用项目配置的章节模型、分析模型、Skill、风格和 MCP 策略；
- 有普通生成、候选采用、失败重试、正文替换和流水线推进的集成测试。
