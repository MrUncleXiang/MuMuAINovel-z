# 验收记录：单副本创建与书籍管理入口

## 已完成

- 书架中的每本书新增“创建独立副本”图标；书籍详情页桌面和手机顶部也提供同一入口，流水线页因复用书籍详情框架同样可直接发起。
- 所有入口复用一个创建面板，不提供临时模型 A/B 并发生成，也不会一次隐式创建两本书。
- 面板默认生成“源书名-章节模型”标题并允许修改；展示章节模型、分析模型、Skill 和 MCP 摘要。
- 用户可选择“从头开始”或“继承已有进度”。继承模式只能选择后端给出的可靠章节节点，并明确说明会整体复制正文、分析、记忆、伏笔和人物状态。
- 没有可靠节点时禁用继承选项并解释原因；读取失败和创建失败保留在面板中显示具体原因；提交期间禁止重复创建和关闭面板。
- 创建成功后刷新书架并进入新书自己的流水线页，明确提示尚未启动，不会自动调用模型。
- 手机端使用接近满屏宽度的单列面板，长模型名允许换行，面板内容可滚动且页面没有横向溢出。

## 自动与真实验收

- 前端生产构建 `npm run build`：通过。
- 目标文件 ESLint：通过。
- Playwright 使用真实服务、真实 PostgreSQL 和隔离账号执行 2/2 通过：
  - 桌面书架打开面板，读取源书配置和第 1 章可靠节点，实际创建继承副本并进入其流水线；
  - 手机书籍详情页打开同一面板，创建按钮可见，页面横向宽度检查通过。
- 浏览器最终运行无控制台错误和失败请求。
- 数据库核对：副本获得全新的项目/章节 ID；第 1 章正文、正式分析和检查点被继承，第 2 章只保留空白章节结构；章节与分析模型配置保持一致。
- 新副本 Pipeline 的 `status` 和 `current_stage` 均为 `idle`，没有自动启动。
- 在事务中只修改副本第一章正文后，源书正文保持不变，随后回滚；证明两本书不是共享同一条可写记录。
- 真实服务 `/health` 返回正常，`git diff --check` 通过；隔离账号、测试书和浏览器临时文件均已清理。

## 产品边界

本任务完成的是“从一本现有书创建一本可长期管理的独立书籍”。副本创建后继续使用 MuMuAINovel 原有的流水线、Skill、章节、剧情分析、伏笔、角色、关系、组织和职业页面。两本已有书的只读并排阅读不属于本任务，也不会在创建副本时触发生成。
