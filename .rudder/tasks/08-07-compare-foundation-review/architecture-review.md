# 对比创作底座架构审查

## 审查结论

当前不能直接进入“复制一本书 + 选择另一个模型”的实现阶段。产品方向已经明确，但现有底座存在四个必须先处理的断点：

1. 流水线没有完整复用普通章节生成配置与前置分析约束；
2. 现有多模型候选在“采用”后没有完整接回章节分析和状态更新链路；
3. 现有数据只能表示角色、关系、组织和职业的最新状态，不能可靠还原任意第 X 章时的状态；
4. Skill、MCP、AI 服务和写作风格中有用户全局资源，不能把“复制书籍选择”误写成“复制或修改全局资源”。

因此，上一轮“同时创建两本副本并自动运行，再进入临时对比页”的原型不能作为正式方案。应保留其中已经验证过的事务复制技术经验，但放弃该产品编排。

## 三种不同生命周期

### 1. 持久化书籍副本

- 是一本新的书，有新的项目 ID；
- 出现在书架，可独立编辑、生成、分析、暂停、继续、导出和删除；
- 复制完成后与源书不共享任何书籍内可写记录；
- 用户在副本中自己选择模型和推进方式。

这是本次需求的主流程。

### 2. 同一章节的多模型候选

- 候选属于某一本书的某一章；
- 多个模型只生成待选版本，采用前不修改正式正文；
- 采用其中一个版本后，才成为该章正式正文；
- 候选批次和结果保存在 `llm_comparison_batches`、`llm_comparison_candidates`。

这是现有功能，可以保留，但“采用后续处理”需要整改。它不能替代一本可长期管理的书籍副本。

### 3. 两本书并排阅读

- 用户手动选择两本已经存在的书；
- 按章节并排查看双方已保存正文；
- 页面本身不生成内容，也不保存唯一结果。

这是上一轮原型中的 `/compare` 页面。当前没有证据证明它是主需求，是否保留应等主流程完成后单独决策。

## 关键发现

### P0：任意“继承到第 X 章”目前无法保证语义正确

`characters`、`character_relationships`、`organizations`、`organization_members` 和 `character_careers` 保存的是当前值。分析服务会原地更新这些记录，没有每章状态快照或完整事件日志。

例如源书已经分析到第 30 章，用户选择只继承到第 10 章：直接复制角色和关系表会把第 11～30 章产生的状态也带入副本。仅过滤正文、分析和记忆不能修复这个问题。

可落地方案必须二选一：

- 先新增“章节状态快照/可重放事件”，再支持任意已形成快照的第 X 章；
- MVP 只允许继承到源书当前最新的连续已分析章节，旧书不提供无法准确还原的历史节点。

不能用“看起来像第 X 章”的不完整复制通过验收。

### P0：章节候选采用后没有进入标准分析链路

`apply_chapter_candidate` 只更新正式 `Chapter` 和 `GenerationHistory`。它没有创建 `AnalysisTask`，也没有触发标准章节分析。因此采用候选后，记忆、伏笔、角色、关系、组织和职业状态不会自动跟进。

### P0：分析候选采用只保存报告，没有应用分析副作用

`apply_analysis_candidate` 只写 `PlotAnalysis`。标准分析中的以下步骤没有执行：

- 提取并写入故事记忆及向量记忆；
- 自动同步伏笔；
- 更新角色心理与存活状态；
- 更新角色关系和组织成员；
- 更新组织自身状态；
- 更新职业进度；
- 形成可被下一章前置检查识别的已完成 `AnalysisTask`。

所以现有分析候选不能直接视为标准分析的等价入口。

### P0：流水线可能在上一章分析完成前继续生成

流水线选下一章时只调用正文前置检查，没有调用 `check_previous_analysis_ready`。正文生成后虽然会异步创建分析任务，但流水线可以先进入下一章，导致下一章使用旧的记忆、伏笔和角色状态。

### P1：流水线界面配置与运行时不一致

流水线运行时把 `style_id`、`skill_key` 固定为 `None`，把 `enable_mcp` 固定为 `False`。界面虽可选择章节模型和分析模型，但自动分析没有收到流水线里选择的分析模型，仍走用户默认路由。

这意味着界面显示“已配置”不等于运行时真正使用。

### P1：多章对比不是顺序创作底座

`batch-compare` 会为范围内多章创建候选，且登记为 `enable_analysis=False`。后面章节的候选不会等待前面章节被采用并完成分析，因此它适合批量预览，不适合推动一本书按上下文连续创作。

### P1：当前克隆原型复制清单不完整

当前未提交的 `ProjectCloneService` 复制了项目、角色、关系、组织、大纲和章节骨架，但至少遗漏：

- `careers`；
- `character_careers`；
- `project_default_styles`；
- 继承模式所需的正文、分析、记忆、伏笔、生成历史和一致状态；
- 向量数据库中的项目记忆集合。

此外，它把角色状态重置为 `active`，只支持从头开始，不符合“继承到第 X 章”。

### P1：书籍独立与全局资源之间需要明确界面

当前资源所有权如下：

| 资源 | 当前所有权 | 可复制内容 | 风险 |
| --- | --- | --- | --- |
| Skill 定义 | 用户级文件资源 | 书籍选择的 `skill_key` 或内容快照 | 书内没有持久化默认选择 |
| MCP 插件定义与启用状态 | 用户级 | 书籍是否允许 MCP、选用范围的快照 | 修改全局插件会影响多本书 |
| AI 服务配置 | 用户级 | 书籍使用的服务 ID、模型及必要运行快照 | 修改/删除全局服务会影响副本运行 |
| 写作风格定义 | 用户级或全局预设 | 项目默认风格关联，必要时冻结提示词内容 | 编辑同一个自定义风格会影响多本书 |
| 流水线推进参数 | 项目级 `config_snapshot` | 可直接深复制 | 当前快照字段不完整 |

“A 书改配置不能影响 B 书”应指书籍自己的选择和运行快照完全独立。全局资源管理页仍是用户级目录；若产品要求在书内直接编辑资源内容，就必须先复制成书籍私有版本或保存不可变内容快照。

## 继承数据分层

### 必须复制的静态设定

- `projects` 的书籍与世界观字段；
- `careers`；
- `characters` 的初始设定；
- `character_careers` 的初始关联；
- `character_relationships`；
- `organizations`、`organization_members`；
- `outlines`；
- `chapters` 骨架；
- `project_default_styles`；
- 项目级创作配置快照。

所有主键必须重新生成，所有外键及 JSON 内部引用必须重映射。

### 继承到 X 时必须复制的语义状态

- 第 1～X 章正文、摘要、字数和完成状态；
- 对应 `plot_analysis`；
- 对应 `story_memories`；
- 截止 X 时有效的 `foreshadows`；
- 支撑前置检查的已完成分析记录；
- 截止 X 的角色、关系、组织、组织成员和职业状态；
- 需要保留的 `generation_history`；
- 新项目自己的向量记忆集合。

`StoryMemory.vector_id` 和 Chroma 集合不能与源书共用。副本需要新 ID、使用新项目集合并重新写入向量。

### 不应直接复制的运行记录

- 正在运行或失败中的后台任务；
- 源书的流水线 ID、当前挂起任务和锁；
- 未采用的候选比较批次（除非以后明确作为审计历史迁移）；
- 源书的任务重试状态。

副本应创建自己的流水线，从 X+1 或第 1 章开始，复制配置但不复制运行锁和进行中状态。

## 建议的深模块

现在普通生成、批量生成、流水线、章节候选采用和分析候选采用分别拼接同一套生命周期，已经发生行为漂移。应收敛成两个深模块：

1. **正式章节落库模块**：接收章节、正式正文来源和生成元数据，统一更新正文/字数/历史，并决定是否启动标准分析；
2. **标准分析应用模块**：接收解析后的分析结果，统一写 `PlotAnalysis`、记忆、伏笔、角色、关系、组织、职业和任务状态。

普通生成、批量生成、流水线和候选采用都只调用这两个小界面，不再各自复制副作用。这样修一次，所有入口同时生效。

## 实施顺序

1. **冻结错误原型**：不合入双副本自动运行和 `/compare` 主流程；保留文档与测试证据。
2. **配置所有权 ADR**：定义项目快照与 Skill/MCP/模型/风格全局资源的关系和编辑语义。
3. **正式章节生命周期收敛**：抽取正式正文落库、标准分析应用两个深模块，修复候选采用。
4. **流水线整改**：复用同一生命周期，补 Skill/风格/MCP/分析模型并等待分析完成。
5. **状态快照能力**：决定并实现任意 X 的状态快照；未完成前只开放可准确继承的节点。
6. **项目克隆 v2**：完成静态表、X 章语义状态、ID/JSON/向量重映射和事务回滚。
7. **单副本 UI**：创建后进入独立书籍，不自动运行，由用户在副本中配置和推进。
8. **项目级阅读对比再决策**：主流程稳定后，再决定是否需要两本书并排只读查看。

## 验证门槛

- 对同一源书分别创建“从头开始”和“继承到允许的 X”副本；
- 修改副本正文、角色、关系、组织、职业、默认风格和流水线配置，源书不变；
- 修改源书同类数据，副本不变；
- 副本 X+1 章生成上下文只能看到 X 及以前的数据；
- 章节候选采用后自动完成标准分析及所有状态更新；
- 分析候选采用后产生与普通分析等价的正式状态；
- 流水线实际调用日志能证明使用了界面选择的 Skill、风格、MCP、章节模型和分析模型；
- 上一章分析未完成时，下一章不会启动；
- 克隆失败后数据库和向量库都没有半成品。
