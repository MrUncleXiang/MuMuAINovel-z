# PRD：对比创作底座架构复盘与任务拆分

> 任务：08-07-compare-foundation-review
> 状态：completed（审查、整改、实现与总验收已完成）

## 结论摘要

当前新增的“选择两个模型 → 自动创建两本副本 → 并行启动 → 临时对比”流程偏离了 MUMUAINovel 的既有能力边界，不能作为正式方案。正式方案应是：

1. 已有项目作为来源，创建一份**持久化的新项目副本**；
2. 副本像普通书一样出现在书架，拥有独立的流水线、配置、章节、分析和角色状态；
3. 用户在副本自己的章节/流水线功能中选择服务、模型、写作风格和 Skill，并决定何时推进；
4. 章节生成仍走 MUMUAINovel 的标准上下文、章节分析、记忆、伏笔、角色/关系/组织状态更新链路；
5. 对比视图只负责选择两本已有项目并阅读，不负责临时生成，也不承担唯一的结果保存机制。

这里的“单副本”不是由旧代码直接证明的事实，而是用户对产品工作流的明确澄清；代码证据证明的是“项目和流水线本来就是持久化边界”，以及现有章节级多模型比较已经有候选持久化和采用机制。

## 代码证据

- `backend/app/models/novel_pipeline.py`：一本项目对应一条持久化流水线，`config_snapshot` 保存模型、预算和推进状态。
- `backend/app/services/pipeline_service.py`：流水线当前调用普通章节后台生成，但把 `skill_key` 固定为 `None`，`enable_mcp` 固定为 `False`，且没有把 Skill/风格作为配置传入。
- `backend/app/api/chapters.py`：普通章节生成支持 `skill_key`、写作风格、MCP，并在保存正文后创建分析任务。
- `backend/app/api/chapters.py`：章节分析会写入剧情分析、记忆、伏笔，并调用角色状态、关系和组织状态更新服务。
- `backend/app/services/chapter_comparison_service.py`、`llm_comparison`：已有章节级候选比较，输入快照、候选结果和采用动作都持久化，适合“同一章节多模型候选”场景。
- `backend/app/models/career.py`、`project_default_style.py`：项目设定还包括职业体系、角色职业关联和项目默认写作风格；当前克隆服务没有覆盖这些数据。

## 必须先决策的边界

1. **已决定：可选继承进度。** 创建副本时，用户可选择“只复制设定，从第 1 章重新写”或“继承到第 X 章”。选择 X 后，必须复制第 1～X 章正文及所有与这些章节对应的过程数据，至少包括章节分析、记忆、伏笔状态、角色/关系/组织状态、生成历史和职业进度；不能只复制正文而遗漏支撑第 X+1 章续写的上下文。具体表级映射必须先按实际代码审计。
2. **已决定：默认复制全部静态设定。** 包括职业体系、角色职业关联、默认写作风格、世界观、角色、关系、组织、大纲和章节骨架。复制后用户可在副本中正常编辑。
3. **已决定：默认复制可编辑的创作配置。** Skill、写作风格、MCP、各阶段服务/模型、分析模型、预算和推进参数必须先审查“当前是否已有用户可编辑界面”；已有界面的设置应复制到副本，缺界面的设置必须作为后续任务补齐交互，不能只存后端黑盒配置。
4. **已决定：副本完全独立。** 复制完成后，A、B 和源书之间不共享可变数据库记录或可写配置；修改任一本书的正文、分析、角色、关系、组织、职业、Skill、模型和流水线，都不得影响其他书。
5. **待审计后决策：项目级阅读对比页面。** 本条指“选择两本已存在的书，按第 N 章并排阅读两边已保存正文”的页面；它不同于现有的“同一章同时让多个模型生成候选，然后选一个正式采用”的页面。是否需要前者、放在哪里、是否只读，必须在既有多模型功能审计完成后再决定，不能默认新增。

## 审查新增的前置约束

1. **任意 X 需要状态快照。** 当前角色、关系、组织和职业表主要保存最新状态。源书已推进到更后章节时，无法仅靠现表准确还原较早的 X；详见 `architecture-review.md`。
2. **候选采用必须接回底座。** 章节候选采用目前未触发标准分析，分析候选采用目前未执行记忆、伏笔及实体状态更新，不能直接视为完整创作链路。
3. **区分全局资源与项目快照。** Skill、MCP、AI 服务和风格定义不都属于单本书。副本复制项目选择和运行快照，不得以修改用户全局资源的方式实现“书内独立配置”。
4. **向量记忆独立。** 继承记忆时必须为新项目重建自己的向量集合，不能复用源项目的 `vector_id` 或集合。

## 实施依赖顺序

`配置所有权 ADR` → `正式章节/分析生命周期收敛` → `流水线整改` → `状态快照` → `项目克隆 v2` → `单副本 UI` → `项目级阅读对比再决策`。

## 非目标

- 不新增一套绕过章节生成/分析的“对比专用写作引擎”。
- 不在弹窗中临时保存正文或只保存在浏览器状态。
- 不把章节级候选比较、提纲比较、分析比较统一重写成项目级并行流水线，先审计已有能力再决定是否整合。

- 九个子任务有依赖顺序、验收标准和回滚方案。
