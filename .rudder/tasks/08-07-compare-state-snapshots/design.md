# 技术设计：章节状态检查点

## 数据模型

新增项目状态检查点表，记录项目、章节、章节号、分析任务、正文摘要、状态、失效原因、配置版本和实体状态 JSON。项目与章节号建立查询索引，同一正文版本只有一个有效检查点。

实体状态 JSON 使用版本化 Schema，包含角色、关系、组织、组织成员、职业及角色职业的完整字段和内部 ID。正文、PlotAnalysis、StoryMemory 和 Foreshadow 不重复塞入快照，由克隆服务按截止章节从原表复制。

## 创建与失效

标准分析所有关系数据和向量记忆成功后，在同一完成阶段生成检查点。正文内容变化、该章分析重做或较早章节失效时，将该章及之后检查点标记失效。

## 旧书

只在能够证明 1..X 章正文存在且最新分析全部完成时，把当前实体状态登记为 X 的检查点。不能证明的历史章不显示为可继承。后台可重算后再逐步增加节点，但不属于首次迁移承诺。

## 重建

后续分析被替换时，从前一个有效检查点恢复实体状态，再顺序物化后续分析。这样避免亲密度和职业阶段重复累加。
