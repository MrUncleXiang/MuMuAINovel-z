# PRD：按章节状态快照与继承节点

## 目标

让系统能够准确回答“这本书分析完第 X 章时，角色、关系、组织、职业、记忆和伏笔是什么状态”，并只向用户开放可以准确继承的章节节点。

## 背景

当前多个项目表保存最新可变状态。源书已经推进到第 30 章时，直接复制这些表无法还原第 10 章状态。`PlotAnalysis` 中的部分前后状态也不足以完整逆推关系、组织成员和职业的所有历史变化。

## 设计要求

1. 在每章标准分析成功后形成一致的状态版本；状态版本必须绑定项目、章节、正式正文版本和分析任务。
2. 快照或事件重放结果至少覆盖角色状态、关系、组织、组织成员、职业关联/阶段、伏笔和记忆边界。
3. 只有正文版本匹配且分析完成的连续章节才能成为“可继承节点”。
4. 较早正文被修改或分析重做时，失效该节点及所有后续依赖节点，直到顺序重算完成。
5. 克隆服务只读取已完成的一致节点，不在克隆过程中临时猜测或拼装状态。
6. 旧项目无法可靠回溯的历史节点不得伪造。迁移后至少可把“当前最新连续已分析状态”登记为可继承节点；更早章节需重放成功后才开放。
7. 状态数据中的角色、章节、关系、组织、职业、记忆和伏笔引用必须可在克隆时映射为新 ID。

## 方案评审项

- 每章完整快照、领域事件日志或“周期快照 + 事件”三种方案的存储量、重放复杂度和纠错能力；
- 关系亲密度、职业阶段等累加变化的幂等键；
- Chroma 向量记忆的版本和重建方式；
- 删除、回滚、重分析时的失效与垃圾清理；
- 旧书迁移和无法还原节点的界面说明。

## 验收

- 源书推进到第 N 章后，可准确读取任一有效节点 X 的状态；
- 从节点 X 创建副本后，X+1 章上下文不含 X 之后的信息；
- 修改 X 章正文后，X 及之后节点立即失效，不能继续用于克隆；
- 修改源书最新状态不会改变已经创建的副本；
- 旧书只显示系统能证明一致的继承节点；
- 快照/事件重放与当时正式项目状态有自动化等价性测试。

## 非目标

- 不在本任务中实现克隆 UI；
- 不承诺从缺少历史证据的旧数据中还原任意章节状态。

## 依赖

- 标准分析物化模块能够在成功提交点调用检查点创建；
- Pipeline 已保证章节按分析完成顺序推进。
