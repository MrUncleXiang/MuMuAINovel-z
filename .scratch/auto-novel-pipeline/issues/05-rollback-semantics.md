# 回滚语义设计（分内容/分阶段）

Type: grilling
Blocked by: 04
Status: resolved

## Question

用户说"可分内容、分阶段回滚"——具体怎么定义？

- "分内容"：回滚只回退章节正文？还是连带大纲一起回退？角色/世界观设定要不要回退（还是永久累积）？
- "分阶段"：回退到上一个检查点？上一个卷？还是任意选定一个历史检查点？
- 回退后已生成的内容怎么处理——标记为"废弃"并保留（方便以后参考/反向采纳）、物理删除、还是存进"废弃版本"分支？
- 回退后"重新生成"怎么衔接：复用原 prompt 还是可以改 prompt 重跑？
- 回退是否是幂等的（回退了再重跑，再回退……直到满意）？

## Answer

**1. 回退内容（分内容）：默认 A，支持 B。**
- 默认（A）：只回退章节正文。大纲、角色、世界观不动（累积资产，回退会破坏一致性）。
- 可选（B）：正文 + 相关大纲一起回退重写。
- 用户明确同意 A 默认、B 支持。

**2. 回退深度（分阶段）：任意历史检查点（B）。**
- 可回退到任意一个历史检查点（第 N 章 / 卷末 / 里程碑），不限于上一个。
- 已确认。

**3. 旧内容处理：纯删除（B）。**
- 回退 = 作废内容直接删除，不留回收站、不存废弃版本、不搞分支。
- 用户明确选择纯 B（即使回退后后悔也无法恢复——接受该风险）。

**4. 重写方式：无需特殊设计。**
- 回退后的重写界面自然提供【写要求】【换模型】【换风格】操作入口（项目已有 regenerate_with_feedback 能力垫底）。
- 用户指出这些本来就是手动操作，不是设计决策，已从票面划除。

**5. 重复回退：幂等，无特殊状态。**
- 回退是同一操作的重复执行（回退→重写→再回退→再重写），不引入额外状态机。

---
Resolved. 默认正文、可选正文+大纲；任意历史检查点；纯删除；重写走现有反馈机制。
