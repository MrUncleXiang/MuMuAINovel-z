# 2. 正文审查 3 步流水线 + 生成后自动审查（先审后析）

日期：2026-08-11

## 状态

接受

## 背景

AI 生成的正文存在错别字、AI 味、表达细节缺失（如"递给老板一张硬币"缺金额与物价）等问题。项目已有多个审稿 SKILL（proofread / aidetect / human / review / continuity），但没有自动环节把它们接进生成流程。审查在生成链中的位置存在两种方案：生成后先分析再审查，或先审查再分析。

## 决策

- 批量生成链中每章顺序：`生成 → 审查（3 步流水线）→ 分析 → 下一章`（**先审后析**——分析必须基于最终定稿正文）。
- 3 步流水线：① proofread（错别字/标点/敏感词）→ ② aidetect+human（表达/细节/AI 味，含"信息完整性"规则）→ ③ review（剧情/伏笔/人设/爽点）。
- minor 问题原地最小修改；major 问题带问题清单打回重写；每章最多 2 轮，超限停下等人工。
- 审查强度（步数）与轮数通过"本书审查配置"（projects.review_config）按项目调整。

## 备选方案

- 先分析后审查：分析结果基于未定稿正文，审查修改后状态不一致，需重做分析 → 未采纳。
- 审查发现问题全部打回重写：成本高、可能越改越偏 → 未采纳（按 minor/major 分级）。
- 把多个 SKILL 拼成一次调用：指令互相打架、顾此失彼 → 未采纳（多步流水线，每步聚焦）。

## 后果

正面：每章生成后质量自动收敛（错别字/AI 味/缺细节）；分析基于定稿正文，状态同步一致；SKILL 零新增（复用现有）。
负面：批量生成变慢（每章多 3-5 次 AI 调用）；存在 2 轮内仍未达标而停下的场景（留报告人工处理，符合预期）。
