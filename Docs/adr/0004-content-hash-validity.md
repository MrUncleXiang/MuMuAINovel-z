# 4. 分析任务绑定 content_hash，过期结果一律丢弃

日期：2026-08-11

## 状态

接受

## 背景

章节分析（记忆提取、角色/职业/组织状态更新、伏笔同步）是耗时的后台 AI 任务。用户在分析期间可能编辑正文——若把基于旧正文的分析结果写入正式状态（记忆库、角色状态、伏笔表），会污染后续所有章节的上下文（"状态与正文不一致"）。

## 决策

- 创建分析任务时记录生成/分析时刻的 `content_hash`（`chapter_lifecycle_service.chapter_content_hash`）。
- 分析完成后、写入正式状态前校验：正文 hash 与任务 hash 不一致 → 任务标记 failed（"分析期间章节正文发生变化，请重新分析"），结果一律丢弃。
- 审查修改正文（生成链中审查先于分析）时同步更新任务 hash，保证分析绑定的是最终定稿。

## 备选方案

- 分析期间锁定章节禁止编辑：体验差、实现复杂 → 未采纳。
- 直接信任旧结果：会产生状态污染 → 未采纳。

## 后果

正面：状态同步与正文永远一致；并发/编辑场景安全。
负面：编辑过正文的章节需要重新分析（用户可感知的一次额外操作，符合预期）。
