# PRD：大纲交互重构（模型入口统一 + Skill 接入 + AI 润色）

## Goal

重构 MUMUAINovel 大纲交互界面，解决三个已确认的问题：

1. **模型选择入口统一**：AI 生成弹窗内「本次模型」与「AI模型」双入口并存、互相干扰的问题，统一为「服务商 → 模型」两级选择，大纲/章节/批量生成弹窗全局一致。
2. **大纲生成接入 SKILL**：大纲生成支持选择 SKILL 并确保真正生效（UI 选择 → 后端注入 → 三条生成路径全覆盖）。
3. **单条大纲 AI 编辑**：编辑弹窗支持 AI 润色、手动创建弹窗支持 AI 起草（结果填回表单、用户确认后才保存）。

整体界面交互重构（问题 D）不在本任务范围，另立任务。

## 背景（用户反馈，2026-08-08 核实）

- 大纲「AI生成/续写大纲」弹窗同时存在旧组件 `AIServiceSelector`（本次使用的AI服务 + 本次模型）与后加的「AI模型」下拉，二者写同一 form 字段 `model`，互相干扰；「本次模型」未选服务商时模型列表为空，看不到已配置的 OPENCODEGO 等模型。
- 编辑大纲弹窗为纯手动表单，无 SKILL 选择、无 AI 编辑能力。
- 后端 `outlines.py` 无任何 skill 相关代码；SKILL 注入仅存在于章节生成（`chapters.py` 1444 行，已验证可行）。
- `backend/app/skills/` 现有 41 个 SKILL，其中 `outline`（大纲设计，三层结构+伏笔总表+平台节奏）与大纲环节直接对口，但从未被任何生成路径使用。

## 需求分解

| 子任务 | 交付物 |
|---|---|
| 08-09-model-selector-unify | 模型选择入口全局统一（大纲+章节+批量弹窗） |
| 08-09-outline-skill-integration | 大纲生成接入 SKILL（单选，三条路径真正生效） |
| 08-09-outline-ai-edit | 单条大纲 AI 润色 + AI 生成起草 |

## 全局约束（跨子任务）

1. SKILL 本期**单选**（接口/UI 均单值，延续既有设计；多技能已决策暂缓）。
2. AI 编辑/起草结果**不直接入库**，必须先填入表单由用户确认。
3. 模型选择交互全局统一为 `AIServiceSelector`（服务商→模型两级），删除各弹窗重复的「AI模型」下拉。
4. 未选服务商时，模型下拉展示**默认服务商**（`is_default=true`，当前为 OpenCode Go）的模型列表。
5. 生成弹窗保留「单模型直接生成 / 多模型比较」两种模式，SKILL 选择在两种模式下都可用（比较模式下所有候选共享同一 SKILL）。
6. 行为兼容：不选 SKILL、不选模型时，行为与现状完全一致。

## 实施顺序

子任务按 **1 → 2 → 3** 串行实施（三者都改动 `Outline.tsx` 弹窗区域，先合入模型统一再叠加 Skill 与 AI 编辑，避免前端冲突）。每个子任务独立验收、独立提交。

## Acceptance Criteria（父级）

- [ ] 子任务 1：大纲/章节/批量生成弹窗均只有一套模型选择（服务商→模型两级）；未选服务商时可见默认服务商（OpenCode Go）模型列表；生成请求正确携带 `provider_config_id`/`model`。
- [ ] 子任务 2：大纲生成弹窗出现「应用 Skill」下拉；选择 SKILL 后，流式/后台/多模型比较三条路径生成时日志均出现「已将 Skill」注入记录；未选 SKILL 行为不变。
- [ ] 子任务 3：编辑弹窗「AI 润色」、手动创建弹窗「AI 起草」可用；返回内容填入表单、用户确认后才保存；带 SKILL 时同样生效。
- [ ] 端到端手测：真实项目完成一次「选 SKILL → 生成大纲」和一次「AI 润色 → 保存」，产物结构（JSON 入库格式）不被 SKILL 带偏。
