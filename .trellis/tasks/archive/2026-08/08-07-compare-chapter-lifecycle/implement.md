# 实施计划：正式章节与分析生命周期

1. 提交一：增加普通章节生成后处理、标准分析副作用和上一章门禁的特征测试。
2. 提交二：提取结构化分析输入构建器，普通分析仍使用原行为。
3. 提交三：提取标准分析物化模块，去掉内部散落提交，由外层统一事务。
4. 提交四：让普通手动分析和顺序批量分析使用物化模块。
5. 提交五：提取正式正文落库模块，让普通后台生成使用它。
6. 提交六：让单模型顺序批量生成使用同一正文与分析模块。
7. 提交七：加强上一章门禁，校验正文版本对应关系、失败和过期状态。
8. 提交八：补向量写入失败、重复任务、正文并发修改和事务回滚测试。

每个提交运行相关 pytest；最后运行后端全测、编译和 `git diff --check`。

回滚：调用者可逐个退回原实现；抽取模块在所有调用者稳定前不删除原兼容入口。
