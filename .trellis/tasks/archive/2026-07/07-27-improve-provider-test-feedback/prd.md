# 改进 LLM 渠道测试反馈

## Goal

让 LLM 渠道连接测试能够容纳较慢的供应商响应，并把最近一次测试状态稳定显示在对应渠道旁边，避免用户只能盯着短暂弹窗判断结果。

## Background

- 全站 Axios 默认超时为 120 秒，vc-grok 最近一次上游调用分别耗时约 135 秒和 241 秒，导致浏览器先报超时、后端稍后成功。
- 当前测试按钮成功时弹一次通知；失败时全局拦截器和页面 catch 可能连续弹两次通知，而且页面上不保留结果。
- 用户明确要求最近测试记录不缓存；刷新或离开后重新进入页面可以清空。

## Requirements

1. 全站普通 API 请求继续保持 120 秒，只有 LLM 渠道“测试”请求使用 300 秒超时。
2. 到达 300 秒仍未收到结果时，显示明确文案：“等待超过 5 分钟，供应商仍未响应，本次测试已超时”。
3. 上游明确返回错误时，显示后端返回的具体原因，例如“Service temporarily unavailable”，不能误写成超时。
4. 渠道列表增加“最近测试”列，按渠道显示：测试中、成功或失败、完成时间、耗时和简短结果。
5. 最近测试记录只保存在当前 React 页面组件内，不写数据库、localStorage 或其他缓存；刷新页面后清空。
6. 测试期间用户可以继续查看和操作页面；结果返回后更新对应行，不要求用户关注弹窗。
7. LLM 渠道测试不再弹成功/失败通知，避免与行内记录重复；其他 API 仍沿用现有全局错误通知。
8. 删除渠道时同步清除该渠道的内存测试记录。

## Acceptance Criteria

- [x] vc-grok 在 120 至 300 秒之间成功返回时，页面显示成功，不再提前报超时。
- [x] 超过 300 秒时，对应行显示失败、实际等待时长和明确的 5 分钟超时提示。
- [x] HTTP 400/502/503 等明确错误显示供应商或后端返回的原因，与超时状态区分。
- [x] 测试中、成功、失败三种状态都显示在发起测试的渠道行内，并包含时间和耗时。
- [x] 刷新页面后最近测试记录消失，数据库和浏览器持久存储中没有新增记录。
- [x] 测试过程不产生重复弹窗；同步模型、保存等其他操作的通知行为不变。
- [x] TypeScript 构建和本次修改文件的 ESLint 检查通过。

## Out of Scope

- 不把渠道测试改成后台任务，关闭或刷新页面会丢失尚未显示的结果。
- 不修改供应商请求重试次数和后端 HTTP 超时。
- 不修复本任务之外已有的全局 ESLint 问题。
