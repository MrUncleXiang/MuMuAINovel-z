## 1. 正文审查体系（讨论→落地全流程）

**需求**：生成后缺少"正文审查"环节（错别字/AI味/缺细节）。多轮讨论定案：

- **顺序**：生成 → **审查** → 分析（先审后析——分析必须基于定稿正文）
- **3 步流水线**：proofread（错别字）→ aidetect+human（表达/细节/AI味，含"信息完整性"规则）→ review（剧情/伏笔/人设）
- minor 原地最小修改；major 打回重写（带问题清单）；每章最多 2 轮
- **卷检查**：卷卡片按钮 → 逐章审查+跨章 continuity → 每章 Tab 问题列表 → 单条/合并 AI 修改（diff 确认）
- **本书审查配置**：左侧菜单入口，开关/步数/轮数
- **审查记录**：章节列表「审查」按钮看历史报告
- 交付：审查引擎服务 + 批量链集成 + 3 个前端组件 + 配置页（trellis 任务 08-11 三件套）

**经验**：SKILL 已存在（proofread/aidetect/human/review/continuity），缺的是"流程环节"——先盘点 SKILL 再设计，不重复造轮子。

## 2. AI 上游稳定性三层排查（本会话最大教训）

**现象**：章节分析间歇失败（空响应/截断/无效 JSON/524）。**三次"根因"逐层深挖**：

| 轮次 | 误判 | 真因 | 修复 |
|---|---|---|---|
| 1 | flash 模型弱 | 缺 UA → Cloudflare 403(1010) 指纹拦截 | base_client 加浏览器 UA |
| 2 | 仍是模型 | 流式长连接 ~100s 被掐断（模型实际生成完，billing 11997 token > 收到 4.3K 字符） | 分析改非流式 |
| 3 | 非流式 524 | Cloudflare 100s 响应上限；flash 大输入(16K)生成超时 | 分析路由用 pro + flash 失败自动兜底 |

**关键实测数据**：flash 13-14K 输入 63-71s 成功；16K 输入 4/4 失败；pro 35-45s 稳。

**教训**：
- 排查顺序：传输层(WAF) → 连接类型(流式/非流式) → 平台限制(100s) → 模型能力。**先查传输再怪模型**（D4F 被冤枉两次）。
- **重视用户的技术质疑**（"flash 1M 上下文不该这样"）——每次质疑都逼出更深一层的真因。
- 批量任务内部分析必须走独立 usage 路由（复用用户默认服务=flash 是批量分析 524 卡死的根因）。
- 应急排查也要建 trellis 任务（两次都没建，后补）。
